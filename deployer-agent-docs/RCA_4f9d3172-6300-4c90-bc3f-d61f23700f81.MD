The redeploy failed at the `build_image` step. Cloud Build's frontend compile (`yarn build`) aborted with a hard compile error. This is an **application source bug**, not a manifest/infra/secrets issue. It must be fixed in the repo (E1) and then redeployed.

## Root cause (reproduced in eph sandbox from this run's source)
`signupChallengeAdminAPI` is imported in 4 files but is **never exported** from `frontend/src/lib/api.js`.

Importers:
- `frontend/src/pages/admin/SignupChallengeAdmin.jsx:4` — uses `.audit()`, `.list()`, `.games()`, `.setEnabled()`, `.setStatus()`
- `frontend/src/components/admin/signupChallenge/ChallengeEditor.jsx:4` — uses `.update()`, `.create()`
- `frontend/src/components/admin/signupChallenge/Panels.jsx:4` — uses `.participants()`, `.assign()`, `.analytics()`

`frontend/src/lib/api.js` defines many `export const xxxAPI = {...}` blocks (authAPI, adminAPI, walletAPI, etc.) but has **no** `signupChallengeAdminAPI` export. The signup-challenge admin UI was added referencing an API client object that was never created/exported.

CRA/webpack treats an unresolved named import as a build-breaking error, so `yarn build` fails and no image is produced.

## Fix (Code — E1)
Add and export a `signupChallengeAdminAPI` object in `frontend/src/lib/api.js` implementing all methods the UI calls, consistent with the other `*API` clients in that file:
- `list()`
- `games()`
- `audit(challengeId)`
- `setEnabled(value)`
- `setStatus(challengeId, status)`
- `create(body)`
- `update(challengeId, body)`
- `participants(challengeId, { status, q })`
- `assign(challengeId, email)`
- `analytics(challengeId, ...)`

Each should hit the corresponding backend `/api/...` route (verify the route paths against the backend router). After adding the export, redeploy.

- Not a manifest issue (Dockerfile/nginx/entrypoint are fine; the build reached the user compile and failed on user source).
- Not secrets, tier, OOM, DB, or domain.
